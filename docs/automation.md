# Automation: the global hooks, scheduled jobs and agent-facing scripts

The long-form record behind the short rules in `CLAUDE.md`: what each piece of
background machinery does, why it is shaped the way it is, and the measurements
that settled each decision. Moved here from `CLAUDE.md` on 2026-10-17 so that
always-loaded context carries the rules and this file carries the history.
Read the section for a script before changing it.

## The "not yet" vs "never" rule, long form

**No flag may mean both "not yet" and "never".** The recurring bug class in this codebase is not a swallowed exception — it is a failure rendered as an absence. A `loading` that a rejected fetch leaves set forever; an empty array returned from a `.catch` that the UI reports as "No matches."; a `null` cache entry that conflates "not a git repo" with "the listing failed"; a `JSON.parse` failure counted as "this line read nothing". Each one produces a confident answer about something nobody actually found out, and each fed a decision — a health score, a spend verdict, an unhook rule. So: a fetch path needs three states, not two (`loading` / `error` / `data`, per `useProjectFanOut`); a cache must not store an error as a negative result; and a scan that could not read its input reports *unknown*, never *none*. When a UI cannot honestly make a claim, it says what it could not reach instead of making a smaller version of the claim. Renderer hooks are testable for exactly this — see `src/features/test-dom.ts` and the two hook tests beside it.

## Global view

`src/features/global/` + `electron/global-config.ts` (channels `global:config`, `global:run-task`, `global:open-file`) — one page for everything that is not per-project: the `~/.claude` hooks, the Windows scheduled jobs, and the settings every session inherits. **Every row is graded on a work probe, never on configuration.** Task Scheduler only knows whether Windows started a process: on 2026-08-23 it reported `Running · LastResult=0` for the (since retired) "claude-hub server" while nothing was listening on the address phones dialed, and it said nothing at all about the vault linker having skipped a day. So a scheduled row's verdict comes from `job-freshness.ts` (log recency plus failure/in-progress detection) — and a task with no mapped probe grades **`unknown`, never `ok`**. Hooks additionally check their script still exists on disk (a moved script leaves a hook that is perfectly configured and dead in every session — the `curate-hook-inert` failure). A row already in trouble also carries what Task Scheduler itself recorded (`runRecordWarnings`), which the page parsed and ignored for a while: the scheduler knows whether Windows **started** the process, the log knows whether the process **did anything**, so joining `LastRunTime`/`LastTaskResult` to the work probe separates *that run produced no output* from *the missing runs never began* — the linker's 2026-08-22 (started 04:36, terminated `0x800710E0`, no log line) and 2026-08-23 (never started) are one of each, and both rendered as "last output 65.6h ago". Note the Windows record that would explain a non-start, `Microsoft-Windows-TaskScheduler/Operational`, is **disabled by default** on this machine. Tasks are enumerated by the `claude-hub` name prefix, so a job added later appears with no code change. A new job's action must be `wscript.exe //B //Nologo scripts\run-hidden.vbs <exe> [args]`. A direct `node.exe`, or `powershell -WindowStyle Hidden`, opens a console that steals focus (2026-10-11: the noon drain did it mid-game). Actions are enumerator-validated like every other write path: `runGlobalTask` accepts only a name from the live enumeration and always does stop→start (all these tasks are `MultipleInstances=IgnoreNew`, so starting a running task is a silent no-op); `openGlobalFile` takes an id from `globalFilePaths()`, never a path. **The page is not the delivery mechanism** — anything `attention` or `unknown` also gets a row in the dashboard's Needs-attention feed, because the linker's missed run *was* already visible on the Knowledge tab, and that is precisely where nobody saw it.

**Spend roll-up.** `job-freshness.ts` also reads what each job's model calls cost (`JobFreshness.spend`: USD and paid-run count for the last 24h, 7d and 30d) off the `cost=` every paid run already logs, and the Automation peek shows the 7d and 30d figures. The number was on disk all along and nothing read it: from 2026-10-14 the curate hook curated its own headless transcripts, 851 of October's 1,375 paid runs, about $80 a week against a normal $8–10, unnoticed for 2.5 weeks until the 2026-10-31 stand-down. Re-measured off the log by this code, curate's 7 days ending Oct 7 / Oct 14 / Oct 21 cost $7.55 / $15.55 / $111.61; recall runs under $2 a week, the drain under $2. Only a run's closing line counts (`done:` / `exit:` / `worker done:`): drain prints the same cost on its mid-run `plan:` line too, and a cached-plan rerun's `$0.0000` made no call. `cost=n/a` is a paid run of unknown cost, counted and shown as such, never $0; an unreadable log is `spend: null` (unknown). A run whose call threw before reporting usage (`exit: … call failed`) writes no `cost=` and is not counted, so the figure is a floor. **Ceiling: $20 per job over 7 days** (twice the highest normal week, `SPEND_CEILING_7D_USD`). Over it, the row goes `attention` with "spent $X in 7 days (ceiling $20) — normal is under $10" in front of its freshness sentence, so it reaches the Needs-attention feed through the same path; `JobFreshness.state` is left alone, and `runRecordWarnings` still keys on the freshness grade (on a current job the scheduler record has nothing to explain). The 7-day window still held the incident's tail on 2026-11-01 ($70.76 over 250 runs, while the days since the fix ran $1–2), so curate reads over budget until about 2026-11-07.

**Hook scope and footprint (2026-11-01).** The curate and recall hooks are registered in `~/.claude/settings.json`, so Claude Code starts them in every session on the machine. The user wanted claude-hub's machinery confined to its workspace, so `electron/hook-scope.ts` decides first, before either hook opens a transcript: in scope is the folder holding the install (`C:\projects`), the sandbox, and every registered project. Anywhere else, curate logs `exit: outside claude-hub's scope` and recall logs the same line once per task-like prompt. Nothing to configure: registering a project brings it in. An unreadable registry narrows the scope to workspace + sandbox and logs why; it never widens. Measured before shipping: 89 of 90 interactive sessions in the previous 30 days were already in scope (the 90th was an empty Desktop test folder), so it costs no coverage today. Moving the hooks into each project's own settings was rejected: it writes into every repo, misses new folders until the hub writes there, and Claude Code may not apply a parent's settings to subfolder sessions. The Settings page's first card (`electron/footprint.ts`) lists everything claude-hub applies outside its folder, read live: the hooks' scope and 30-day reviewed / stood-down counts, the scheduled tasks, the hub-written deny rules per project, and the data folders. Its curate count is closing lines with `cost=` (sessions actually read), not `start` lines, which include every headless stand-down.

## Agent-facing scripts (`scripts/`)

- `register-skill.mjs <sourceSkillPath> <targetProjectPath>` — copies a skill folder into a project's `.claude/skills/`, refuses on name conflict. Same mechanism the desktop UI's "Copy to project"/"Promote" actions use.
- `log-to-vault.mjs "<title>" "<content>"` — writes/appends a note to the knowledge vault (`C:\projects\claude-hub-vault`), dedups against `index.md` by title match.
- `curate-session.mjs` — **enabled as a SessionEnd hook globally** (`~/.claude/settings.json`; moved from claude-hub's project `.claude/settings.json` to global on 2026-07-08 so vault-worthy findings from *any* project get flagged, not just claude-hub — claude-hub's project settings is now `{}`). Two-tier curation at session end (see `electron/curate-core.ts`): a cheap **haiku** triage answers "is there plausibly anything here?" and, only on a yes, a skeptical **sonnet** extraction runs, dedups against the vault index, and queues one or more candidate notes to `_inbox.md`, each tagged with the originating project name, for manual review (never auto-commits). Recursion-safe via `curateStandDownReason` (`curate-core.ts`): it exits before any paid call when `CLAUDE_HUB_HEADLESS=1` (the hub's own `claude -p` calls) or the transcript's entrypoint is `sdk-cli` (any headless run, including the trading bot's scheduled legs). It used to rely on the `MIN_TURNS_FOR_REVIEW` pre-filter alone; from 2026-10-14 its own triage transcripts parsed as 4 messages and passed it, and the hook curated its own calls: 851 of October's 1,375 paid runs, then 258 extracts in a row (2026-10-19 → 10-31) that queued nothing. Found 2026-10-31; a sample of real sessions all log `entrypoint: cli`. Strips a markdown code fence from the model's output defensively — the models wrap JSON in ` ```json ` despite being told not to. The queue-time dedup here is still **title-exact only**, so semantic duplicates re-queue across sessions — that backlog is drained by the job below, not fixed here.
  **One shared vault, not one per project** (decided 2026-08-18, measured — do not re-litigate without new numbers): 10.1% of attributable link edges cross a project boundary, and those are the highest-value edges precisely because a cross-domain link is the one you'd never think to look for. Splitting would also leave most projects with a 5–14 note corpus, which is too small for recall to match against, while one project (skyrim-agent) holds 114 of 202 notes. The thing per-project splitting was reaching for — curation tuned to a project — is already available *without* splitting storage, via this script's `--rubric` flag. A project may still opt out entirely with `--inbox` (Rational does), and the global hook stands down when it sees that.
- `vault-recall.mjs` — **the read-side mirror of the curate hook**, enabled as a global UserPromptSubmit hook (`~/.claude/settings.json`, 2026-08-09) after the evidence-of-use audit showed capture was fully automated but recall had fired ~10× ever. Three-phase because UserPromptSubmit blocks the prompt and a `claude -p` call is ~13-16s even warm: the first substantive prompt of a session only records that it happened (`.seen`, free), the **second** spawns a **detached worker** (same script, `--worker`) that runs a haiku match of the task against the vault's note titles (logic in `electron/recall-core.ts`), and a later prompt delivers the result. **The match reads the first prompt AND the latest one** (`composeTaskContext`), which is why `.seen` stores the prompt text rather than an empty file: paying on the second prompt had silently made the second prompt the *only* thing the matcher saw, and the task statement is almost always the first — what it was being paid to match against read like "should we go with your recommendation now?". Replayed over 14 real no-match sessions (2026-08-23): shipped input 1 hit, first prompt alone 5, both together 7, same model and same single call. Both, not just the first — the follow-up killed a false positive the opener raised alone. Harness-written turns (`<task-notification>`, `<local-command-stdout>`) are not prompts and are now rejected outright; 9 of the first 100 paid calls were spent reading one. Paying on the second prompt rather than the first is deliberate (2026-08-18, measured): 31 of 86 sessions never sent a second prompt, so a first-prompt call bought an answer with nowhere to land, while only 7 stopped at exactly two — net -24 wasted calls. Sessions whose cwd is under the OS temp tree (parallel-build worktree arms) are skipped entirely for the same reason (`isEphemeralSessionCwd`); do NOT widen that to "sandbox", which was measured and would have destroyed 4 of the 11 injections ever delivered — high-confidence matches only, validated against the real index (anti-hallucination), max 3, injected via stdout with the greppable `[vault-recall]` marker. Silent on everything else; ~120ms on the hot path. Recursion/spend guards: `CLAUDE_HUB_HEADLESS=1` (set centrally by `electron/call-claude-core.ts`, which every hub automation `claude -p` call goes through — plus sandbox's Draft Learnings spawn, which sets it directly; prompt-size ceilings alone are NOT enough, a triage of a small transcript slips under them), plus a 4000-char prompt ceiling and a 25-attempts/day cap. State + offer log in `scripts/.vault-recall-state/` + `scripts/vault-recall.log` (the log is the experiment's offer-denominator; hit rate = transcript scan for the marker followed by reads of the offered notes, **both via the Read tool and via a shell command naming the note file** — counting Read alone under-reported reads by half). **The experiment's kill criterion has been answered in its favour** (2026-08-18, restated 2026-08-23): 6 of 18 delivered offers were actually read — the 3 first recorded, plus 3 the scorecard could not see because they were opened with `cat` — against a prior baseline of ~10 vault lookups in the vault's entire history, so the hook stays. Note the matcher runs on the `haiku` alias, which moves to each new Haiku release on its own — hit rates from before and after such a move are not from the same matcher.
- `recall-scorecard.mjs` — **the experiment's verdict meter**: parses `vault-recall.log` and scans each delivered session's transcript for reads of the offered notes (logic in `electron/recall-scorecard.ts`), printing attempts → offers → delivered → read → spend. The same numbers back the Knowledge view's "Recall experiment" line (`vault:recall-scorecard` channel), so the unhook-vs-keep and auto-promote decisions read off evidence, not vibes.
- `audit-dossiers.mjs` / `audit-catalog.mjs` — **the evidence substrate for a functionality audit** (`docs/functionality-audit.md`, and the global `council-audit` skill). The catalog enumerates every feature from a real source — views from `src/nav.ts`, capabilities from `IPC_CHANNELS`, automations from the global hooks plus Task Scheduler — and the extractor writes one dossier per feature: its claim, entry points and whether the renderer actually calls them, invocation evidence from logs / artifacts / a scan of every transcript, its failure surface, and its cost. `node scripts/audit-dossiers.mjs [outDir]`, ~16s. **A probe with no first-party evidence grades `unknown`, never `unused`** — the whole point is that "never measured" and "measured zero" stay different facts. Re-derive the catalog rather than trusting it: **nine separate false readings across two rounds** (a path one level too shallow, a tool a child process could not launch, a detector that matched nothing, a marker string that also lived in CLAUDE.md, a transcript probe that could only ever measure people *reading* the code, and an `inPreload` grep for method names that `buildInvokeApi()` generates rather than writes) came out of this extractor before anyone read it, each of them this codebase's own bug class inside the tool built to detect it. **A first-party transcript probe must declare a `lineTest`** — a marker in a transcript otherwise proves only that the string was in the session, which includes every session that read the source containing it. And verify the properties you did *not* think to check: the round-2 harness tested `calledInRenderer`, never tested `inPreload` beside it, and shipped 75 false negatives.
- `link-vault.mjs` — **vault linker**: no-flag = whole-corpus backfill (one sonnet call over every note → `_links.jsonl` sidecar); `--incremental` = per-note calls for new/changed notes only (mtime state in `.link-vault-state.json`, logic in `electron/vault-linker-run.ts`), formerly the daily 04:30 Task Scheduler job "claude-hub vault linker", **unregistered 2026-10-31**: recall matches note titles only and never reads `_links.jsonl`, so the edges serve only Obsidian and the graph view, which the user does not use (the vault's purpose is keeping sessions from repeating mistakes). Inbox approve, quick capture and Relink still link per note. To restore: action `wscript.exe //B //Nologo "C:\projects\claude-hub\scripts\run-hidden.vbs" "C:\Program Files\nodejs\node.exe" "scripts\link-vault.mjs" "--incremental"`, working directory `C:\projects\claude-hub`, daily 04:30, and re-add the `linker` row to `JOBS` in `electron/job-freshness.ts`. The interactive write paths (inbox approve, quick capture) also fire a non-blocking per-note link, and the Knowledge view's Relink button drives the same recompute via `vault:recomputeLinks`. Every linker run also re-materializes each note's `## Related` block (below).
- `materialize-links.mjs` — renders the `_links.jsonl` edges into each note body as a marker-delimited `## Related` `[[wikilinks]]` section so Obsidian (pointed at the vault) gets a real graph/backlinks. Pure helpers in `electron/vault-related-core.ts`; every hub body-parser strips the block, so materialized links never count as authored edges/backlinks (which would inflate node sizes), never reach a link prompt (no self-feed), and never pollute drain excerpts. Linker runs keep blocks fresh automatically — this script is the manual backfill/self-heal (`--dry-run` previews; execute backs up top-level notes to `_backups/` and advances `.link-vault-state.json` mtimes for in-sync notes so the daily job doesn't re-fire). Both paths also regenerate the vault's `MOCs/` entry pages (`electron/vault-moc-core.ts`): `Map of Content.md` sections = link-graph communities (`shared/community.ts`) headed by each cluster's hub note, `By origin.md` = `project:` frontmatter (origin-of-discovery, deliberately not topic). `MOCs/` is a subfolder precisely so the hub's top-level-only vault scans never parse the generated pages back.
- `drain-inbox.mjs` — **batch semantic dedup of `_inbox.md`**, registered as a daily Windows Task Scheduler job "claude-hub inbox drain" (noon; **auto-promote mode since 2026-08-18**). One whole-inbox **sonnet** call (`electron/inbox-drain-core.ts`) clusters same-finding candidates by meaning (not title) and flags ones already captured by a vault note; a deterministic policy in code (never the model) then acts on the clusters. Modes: `--dry-run` (preview, writes nothing), `--dedup-only` (collapse duplicates, promote nothing), default (also auto-promote **high-confidence** cluster reps into the vault) — **default is what the scheduled task now runs**, enabled 2026-08-18 once the gate's stated condition was met (the recall-injection hook exists and shows hits). Re-gate by putting `--dedup-only` back in the task's Arguments. Fails safe: a strict partition-validated plan (`parseDrainPlan`) or any LLM/parse error leaves the inbox untouched. The vault is not git, so every execute run backs up `_inbox.md` into `_inbox-backups/` (subfolder, so it stays out of the top-level graph scan; pruned to the last 5). An unchanged-inbox guard + a plan cache keyed by inbox hash mean idle scheduled runs and a preview-then-commit both avoid a redundant LLM call. Initial drain 2026-07-11: 130 → 53 entries (77 duplicates dropped).
- `record-verify.mjs` — **the floor recorder**: runs a registered project's `verifyCommand` and appends the outcome to `verify-ledger.jsonl` (append-only, machine-local, gitignored); `getFloorStatus()` in `electron/floor-core.ts` reads it back for the dashboard's "Floors green" tile, the Needs-attention footer, and the Projects-tab floor card. `--all` runs every project that has a `verifyCommand` and is **registered as the daily 04:45 Task Scheduler job "claude-hub floor verify"** (`StartWhenAvailable`, so a missed run fires on wake rather than punching a hole in the streak). A project whose path is missing is skipped, never recorded red — a missing checkout is not a test failure. `--hook` (Stop-hook) mode still exists and is still dormant; the scheduled job replaced the reason to enable it. **Why it exists as automation and not a button** (2026-08-23, measured): with recording manual, the ledger held 12 runs in 52 days, and the two floor numbers on screen were both artifacts of that — the streak counted *calendar days since the last red run*, so skyrim-agent's single green run in July was still claiming a "42-day streak" six weeks later, and the KPI tile counted "green" from `latest.ok` with no age term at all, so a fortnight of silence read as an all-clear. Both are now honest: **`computeStreakDays` counts consecutive days that actually have a green run, anchored to the last run rather than to now** (so it cannot grow while nobody runs anything), and every view classifies a floor through one shared `floorState()` (`src/features/floor/useFloorStatus.ts`) that returns green / red / **unverified** — the third state being the point, since "not re-checked in 48h" is neither a pass nor a failure. Disable by unregistering the task; the numbers then correctly decay to "unverified" instead of freezing green.
- `screenshot-app.mjs` — launches the real built Electron app under Playwright and screenshots every view against real data (`npx vite build` first). The way to verify a UI change end to end.
- `main-thread-budget.mjs [budgetMs=250]` — times how long each read-only IPC handler and the live sweep hold the main thread against the real `~/.claude` data, and exits 1 if any exceeds the budget. A window goes "Not responding" after ~5s without pumping messages, and handlers that each block a few hundred ms stack into that when a view fires them together. Written 2026-10-20 after the app froze while several sessions were writing: the live sweep was re-reading up to 1MB of each hook transcript's head every 1–2s, and `getGlobalConfig` ran PowerShell synchronously on every Home load. It runs against a temp `APP_ROOT` holding a copy of `registry.json` (taken from `APP_ROOT` when set, since a worktree has none), so caches are measured cold and the running app's state is never written. It skips handlers with side effects (`getExtensions` re-checks by spawning every MCP server). `getUsage` returns at once and indexes in the background, so its chunks can inflate the rows measured after it. First run, 111 measurements: 6 over 250ms, worst 740ms (`auditBoundary` on claude-hub). Real data, ~1 minute, so it is a script and not part of `npm test`.

## Retired: the hub server and session steering (2026-10-17)

`scripts/hub-server.mjs` served the renderer plus the whole invoke surface over
Tailscale so the hub worked from a phone, and owned live Agent SDK sessions that
the desktop steered through `electron/session-proxy.ts`. Retired because the
phone was never used and the steering path had one recorded session ever
(`hub-sessions.json`, 2026-08-22); Claude Code's own remote control and push
notifications cover the away-from-desk case. The Sessions view stayed, read-only
over on-disk transcripts, with Resume in terminal in place of Adopt. The
"claude-hub server" scheduled task was unregistered. The full implementation —
Tailscale name-matching, the late-bind retry, the loopback dual-bind, the
firewall notes — is in git history before commit `324666e`.
